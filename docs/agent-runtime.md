# Read-only agent runtime (not routed or enabled)

`FoodContext(client, user_id, university, planning, targets, restrictions=(), allergens=(), preferences={})` accepts **only service-authenticated** identity and trusted, normalized profile values. Construct a fresh context each turn after loading current profile/preferences. Do not pass a client JSON profile through to this constructor. Targets use the existing application calculation; the runtime does not duplicate that formula. University ID/display name and hall ID/name/slug are resolved through `universities_config.json`; unsupported scope and missing meal fail before a model call.

`AgentTurn(context, TurnRequest, conversation_id, SDK_history, client=AsyncOpenAI(...))` exposes `stream()` yielding typed v1 events. Its `state`, `history`, and `assistant_text` are the integration interface. The endpoint must authenticate, authorize rollout/subscription/policy, claim the request with `AgentStore.claim_turn`, and supply that owner's `load_history` before constructing this object. Only the claim winner runs the model. After normal completion, timeout or disconnect, close the iterator and persist the known terminal outcome with `finish_turn`; reconcile with the same request ID. This module itself makes **no writes** and does not claim endpoint persistence is implemented. Empty assistant text is permitted by the store.

Menus are exact owner-campus/hall/calendar-date reads of full stored rows, never the legacy provenance-stripping retrieval result. The shared validator requires an aware fetch timestamp, a maximum age of 24 hours, explicit meal membership, trusted complete nutrition, canonical selection IDs and current hard restrictions. A proposal is emitted only after deterministic validation. Food logs are explicitly filtered and revalidated by owner/date. Device meal-completion state is not synced to a server source, so the intake tool reports only remaining targets after food logs and explicitly refuses a completeness claim. Completion synchronization remains a release gate.

Limits: eight SDK turns, 2048 output tokens per model turn (maximum 16384 across eight turns), at most sixteen tool calls, two validation calls (initial plus one repair), 16000 assistant characters, 480 application events plus terminal, 128 replay items/256 KiB, 128 KB menu context, 500 food logs, 30-second per-HTTP timeout, zero HTTP retries, and at most 45 seconds overall. The caller may shorten the deadline to fit measured deployment limits, never increase it here. Excessive/failed/cancelled runs terminate with sanitized errors and discard incomplete history. No fallback generator is called. SDK cancellation stops the model tasks; an already executing synchronous database read dispatched to a thread may finish after cancellation but cannot write.

Only the SDK `to_input_list()` is retained. There is no server conversation/previous-response continuation. Tracing and sensitive data inclusion are disabled, model storage is disabled, SDK private-data logging opt-ins fail closed, and SDK model/tool/error logs are suppressed within this run. No prompts or profile values are logged by these modules. Progress comes from actual SDK tool-call events. Hosted search has a strict zero-call bound in this phase; consequently citations are empty. Search with public-only query isolation and verified hosted-call limits is a separate integration gate, not a simulated tool.

## Dependency execution evidence

The foundation import checks did not expose an execution incompatibility: `openai-agents==0.8.1` with resolved `openai==2.54.0` raises a Pydantic error when its `Usage` constructs `InputTokensDetails(cached_tokens=0)` because that client additionally requires `cache_write_tokens`. Both manifests now pin `openai==2.26.0`, verified in an isolated Python 3.11 environment. The actual Runner/Responses stream, function-tool invocation, usage creation and SDK replay execute against synthetic HTTP responses. No paid/model/network request is used by tests. Package constraints were checked against [OpenAI client metadata](https://pypi.org/pypi/openai/2.26.0/json) and [Agents SDK metadata](https://pypi.org/pypi/openai-agents/0.8.1/json).

`tests/test_agent_runtime_unit.py` contains eleven focused checks, including Unicode, exact tool schemas without user arguments, deterministic portions, one repair, owner-filtered intake, successful terminal state, deadline/cancel, close after terminal, private-log suppression, cross-task stream closure, tool limits before database reads, and the real SDK HTTP boundary. The dedicated companion testing agent owns broader independent runtime/tool cases.

Dependencies: backend PR #3 meal validation, #4 meal tests, #5 persistence, #6 persistence tests, #7 source normalization. Runtime integrates their exact histories; no migration has been applied to production. Rollout remains off. Required before activation: separately reviewed companion tests, route/policy/persistence integration, completion sync, authorized memory/actions/search, existing route adapters, additive schema deployment, working live-model credentials (last check returned 401), staging streaming, actual Vercel limits, privacy inspection, measured latency/cost and rollback drill. Removing/disabling future callers rolls back this runtime without deleting stored meals or conversations; Gemini scanning and rollback are unchanged.
